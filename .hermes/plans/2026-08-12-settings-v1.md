# Settings V1 and Dynamic AI Control Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Add a persistent Settings surface at the bottom of the left sidebar and make local SIGINT audio AI safely controllable at runtime.

**Architecture:** Store receiver-wide settings as versioned, allowlisted JSON sections in the existing `app_settings` SQLite table. Expose authenticated no-store APIs for reading and patching sections. Keep browser-only layout preferences in the browser, while Sidebar and AI policy persist on the receiver. The analysis worker consults the effective AI policy before queueing, backfilling, or claiming jobs; disabling it never deletes evidence or queued jobs and lets an already-running subprocess finish.

**Tech Stack:** Next.js App Router, React, TypeScript, Drizzle + better-sqlite3, Node test runner, Playwright.

---

## Scope V1

- Fixed `/settings` link at the bottom of the existing sidebar.
- Settings is not an RF module and is never persisted as the last operational module.
- Sections: General, Sidebar, AI & Analysis, Diagnostics.
- Versioned persisted records: `settings.general.v1`, `settings.sidebar.v1`, `settings.ai.v1`.
- No secrets, arbitrary paths, bind addresses, API tokens, shell commands, model downloads, capture deletion, RF acquisition, session restart, or live radio mutation.
- AI live toggle with safe pause semantics.
- Explicit `Process queued captures` action, separate from enabling AI.
- Import/export and arbitrary reorder UI are deferred until the core contract is proven.

## Task 3: Dynamic AI policy and status

**Files:**
- Modify: `src/server/analysis-worker.ts`
- Test: `tests/analysis-worker-settings.test.ts`

**Required behavior:**
- Disabled: no new audio jobs, no automatic backfill, no job claim.
- Existing queued jobs remain queued.
- Running analyzer finishes and writes its result.
- Enabled: new captures can queue normally, but historical backfill occurs only through explicit action.
- Status includes effective enabled flag, runtime installed/health, worker running/processing, queue counts, current job, and latest result without secrets or raw paths.
